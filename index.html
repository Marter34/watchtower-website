Quick start

  1. Invite Watchtower using the invite button.
  2. Review the requested permissions in Discord.
  3. Place the bot's role above roles it needs to moderate, but below trusted administrator roles.
  4. Configure staff roles, logging channels, and emergency settings using features actually supported by your bot build.
  5. Test in a private server before relying on protection in a live community.
Permission warning: The provided invite URL requests Administrator permission. That is highly privileged. Consider generating a least-privilege invite based on the permissions the bot actually needs.

Anti-raid protection

Anti-raid systems can watch for unusually fast waves of new members. Choose thresholds based on your server's normal join rate and avoid settings that automatically punish members without review.

Recommended setup

  • Set a reasonable join threshold and detection window.
  • Choose whether a trigger alerts staff, enables verification, or requests a temporary lockdown.
  • Document how staff can reverse mistaken actions.
  • Test during a controlled event before enabling automation.

This guide does not confirm that a detector is active in the current bot deployment.

Anti-nuke lockdown

Anti-nuke protection aims to respond to suspicious destructive activity such as mass channel or role changes. Automated actions can cause damage if configured too aggressively.

  • Keep an owner-controlled recovery path outside the bot.
  • Restrict sensitive controls to trusted administrators.
  • Log trigger events and responses where technically possible.
  • Test lockdown and restoration in a separate server.
  • Do not assume deleted messages or channels can always be restored exactly.

Troubleshooting

Bot appears offline

Check the bot host, environment variables, Discord Developer Portal settings, and application logs. GitHub Pages cannot determine bot uptime by itself.

Missing permissions

Check role hierarchy, channel-specific overrides, and the invoking member's permissions. Avoid granting Administrator as the first troubleshooting step.

1. Introduction

This Privacy Policy explains how Watchtower ("WT," "Watchtower," "the Bot," "we," "our," or "us") collects, uses, stores, and discloses information when users and Discord communities interact with the Bot.

Watchtower provides Discord moderation, automated protection, anti-raid detection, anti-nuke monitoring, emergency lockdowns, and server configuration.

This policy describes the intended data practices of Watchtower. Actual practices must match the deployed Bot, its configuration, and applicable legal requirements.

2. Information We Collect

Depending on the features enabled in a server, Watchtower may process the following information.

A. Discord Identifiers

  • Discord user IDs.
  • Discord server (guild) IDs.
  • Channel and role IDs.
  • IDs of users who perform moderation actions.

These identifiers help Watchtower distinguish users, servers, channels, and roles.

B. Moderation Records

When moderation features are used, Watchtower may store:

  • Warnings, timeouts, kicks, and bans recorded by the Bot.
  • The affected user's ID and the moderator's ID.
  • Reasons supplied by users or administrators.
  • Case numbers and action timestamps.
  • Relevant action outcomes and error records.

Moderation reasons may contain personal information if users include it in their submissions. Server administrators should avoid entering unnecessary sensitive information.

C. Anti-Raid and Security Events

Watchtower may record:

  • Member join timestamps and join-rate counts.
  • Suspicious activity indicators and security alerts.
  • Quarantine and escalation actions.
  • Relevant channel or role deletion events.
  • Mass-ban indicators and available audit-log attribution.
  • Lockdown start and end times.
  • Triggering events and permission-restoration attempts.
  • Trusted users, exempt roles, and server security settings.

Watchtower may inspect relevant Discord audit-log events when authorized and permitted by Discord.

D. Server Configuration

Watchtower may store:

  • Moderation log channel IDs.
  • Quarantine role IDs.
  • Anti-raid and anti-nuke thresholds.
  • Lockdown state and saved permission-overwrite data.
  • Configured exemptions, allowlists, and enabled features.

This information allows Watchtower to maintain separate configurations for each server and preserve active security states across restarts.

E. Message Content

When message-filtering or anti-spam features are enabled, Watchtower may inspect message content to detect spam, prohibited terms, or suspicious links.

Message content may be processed temporarily or retained as limited moderation evidence, depending on the implemented features and configuration.

Watchtower does not promise that message content is never stored. The operator must ensure that the deployed implementation and its retention settings accurately reflect the practices described in this policy.

Watchtower uses information to:

  • Identify patterns of destructive administrative actions.
  • Activate and manage emergency lockdowns.
  • Restore permission settings changed by the Bot where possible.
  • Preserve server configuration and security state across restarts.
  • Investigate errors, prevent abuse, and maintain service reliability.

Watchtower does not sell personal information to advertisers.
